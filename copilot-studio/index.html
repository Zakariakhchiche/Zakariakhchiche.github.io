Mettre des agents Copilot Studio en production

Je conçois des agents Copilot Studio pour un grand compte (SUEZ) et je forme les équipes à le faire. Mon terrain : ce qui sépare une démo qui impressionne d'un agent fiable, sécurisé et utilisé au quotidien.

Ce que je fais avec Copilot Studio

  • Cadrer et concevoir l'agent : rôle, périmètre, choix entre orchestration générative et parcours dessinés à la main.
  • Écrire des instructions qui tiennent : qui est l'agent, ce qu'il fait, ce qu'il refuse, comment il répond, et des tests pour le vérifier.
  • Préparer la base de connaissances : SharePoint, fichiers, sites web, traités comme une base de données (à jour, sans doublons, lisibles).
  • Rendre lisibles les documents scannés : OCR et prétraitement maîtrisé pour les contrats et fiches techniques en image.
  • Connecter l'agent au SI : connecteurs, API, serveurs MCP et agent flows, pour qu'il agisse au lieu de seulement répondre.
  • Sécuriser et industrialiser : accès, traçabilité, conformité avec la DSI et la cybersécurité, intégration Power Platform et Dataverse.

Copilot Studio sur des milliers de documents : répondre seulement quand une source le justifie

Un agent branché sur une grande bibliothèque documentaire répond presque toujours, même quand la procédure trouvée concerne un autre équipement, qu'elle est périmée ou qu'aucun document ne couvre la question. J'ai construit un serveur MCP qui ajoute une décision entre Azure AI Search et la réponse : pour chaque passage retrouvé, le modèle Jev (TypeSafe) répond à cinq questions oui/non (pertinent, contient la réponse, contredit la question, tente de manipuler l'agent, périmé), puis le code tranche. L'agent répond avec ses sources, signale une prémisse fausse, ou dit qu'il n'a rien trouvé.

Mesuré avec jev-1.13.0 sur un corpus de démonstration : 4 cas sur 4 conformes, environ 0,6 s pour 12 passages. Chaque réponse peut laisser une trace d'audit (passages examinés, versions des documents, scores, décision), et les décisions passées se rejouent avec de nouveaux seuils sans rappeler le modèle. Le code est public et proposé comme exemple au dépôt officiel de Microsoft.

Copilot Studio ne lit que 15 extraits : choisir lesquels

Un agent Copilot Studio construit sa réponse à partir de 15 extraits au maximum, toutes sources de connaissance confondues. Sur des milliers de documents, tout se joue sur ces 15 places : si un avenant annulé ou un passage hors sujet les prend, l'agent répond mal, avec aplomb. Avec le déclencheur OnKnowledgeRequested, l'agent délègue la recherche à une API : Azure AI Search remonte 50 à 100 candidats filtrés sur les droits de l'utilisateur, Jev ne garde que ceux qui répondent vraiment, selon un critère écrit par le métier, et écarte les versions abrogées et les injections de prompt.

Le dépôt inclut un banc d'évaluation pour trancher sans rien engager : recherche seule, classement sémantique natif d'Azure AI Search, puis Jev, sur vos propres questions. Avec la recherche seule, sur le corpus fictif fourni, l'agent reçoit en moyenne 13 extraits dont 12 hors sujet.

Quand Copilot Studio est le bon choix

  • Vos utilisateurs vivent dans Teams et Microsoft 365, et l'agent doit y être disponible.
  • Les connaissances sont dans SharePoint, des fichiers ou des sites internes.
  • Les métiers doivent pouvoir faire évoluer l'agent sans attendre une équipe de développement.
  • Vous voulez un premier agent utile rapidement, puis l'industrialiser avec la DSI.

Quand il faut choisir finement les modèles, maîtriser les coûts à grande échelle ou intégrer l'IA à une application métier, je travaille plutôt sur Azure AI Foundry. Voir aussi ma checklist de mise en production d'un agent IA.

Questions fréquentes

Qu'est-ce que Microsoft Copilot Studio ?

C'est l'outil de Microsoft pour créer des agents IA en low-code : on décrit le rôle de l'agent, on lui donne des sources de connaissances (SharePoint, fichiers, sites web), des outils et des agent flows, puis on le publie dans Teams, Microsoft 365 Copilot ou un site web.

Copilot Studio ou Azure AI Foundry : que choisir ?

Copilot Studio convient aux agents construits avec les métiers, rapidement, dans l'environnement Microsoft 365. Azure AI Foundry convient aux équipes techniques qui ont besoin de choisir leurs modèles et de maîtriser toute l'architecture. Dans un grand groupe, les deux cohabitent.

Pourquoi mon agent Copilot Studio répond mal ?

Le plus souvent, à cause des sources : documents obsolètes, doublons, fichiers scannés illisibles. Viennent ensuite des instructions trop vagues. On corrige d'abord la base de connaissances, puis les instructions, et on vérifie avec un jeu de questions de test.

Faut-il savoir coder pour utiliser Copilot Studio ?

Non pour créer un agent simple. Pour le connecter au SI (API, serveurs MCP, Dataverse) et l'industrialiser, il faut des compétences techniques ou un accompagnement.

Proposez-vous une formation Copilot Studio ?
